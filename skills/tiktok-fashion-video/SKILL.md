Use this for the practical product-to-video workflow. Follow the user's current scope and reuse verified product caches. It does not authorize extra paid versions, product edits, TikTok posting, or unrelated workbook changes.

Read [operations.md](references/operations.md) for commands, resume behavior and browser access. Each video specification is an independent Markdown file under `workflow/`. Select one with a separate request line `规则文件：filename.md`; omission uses the existing plus-size fashion document. The runtime injects only the selected file through `fashion_prompt.py`; read [script-rules.md](references/script-rules.md) for its source and review process, with current user instructions taking precedence. Read [workbook.md](references/workbook.md) for database lookup and Excel export. [verified-run.md](references/verified-run.md) states what the first real run demonstrated and its limitations.

## Agent Node runtime

A PID and the supplied identity photo are sufficient to start product lookup on the configured Linux server. The node ships its collector and the API workflow template. Do not ask the user to supply a workflow or a prewritten video prompt. `read_skill_resource("scripts")` lists the actual helpers. Read [browser-setup.md](references/browser-setup.md) only for installation, login or migration errors.

Keep the creative script and execution notes separate. `--prompt-text` contains only the selected specification's finished script, including its chapter groups and fully developed shot fields. For the default fashion rules, use a title and thirteen level-two numbered headings, with separate character groups, scene event chain, per-shot voice/camera/action/transition details, and grouped consistency requirements. Keep concise speech while expanding visual and performance directions. Do not copy the example's product, setting, cast, dialogue or props into unrelated tasks.

The runtime separately injects [TikTok posting rules](../../workflow/TikTok发布文案与标签规则.md). Standalone use must read that file before writing posting copy. Generate one English caption with relevant emoji and the requested hashtags from the verified product and script, comparing available history. On every prepare, pass `--caption-text CAPTION --hashtags TAG1 TAG2 ...` together with the full script; these are saved only to `post-copy.json`, not the video prompt. Revise them when the product, story or selling points change. Do not put captions/hashtags into sections 7 or 8, which contain only the complete dialogue and its Chinese translation.

On prepare, also pass `--execution-notes NOTES` to save `execution-notes.md`: state product verification evidence, crop selection rationale, available history and deduplication scope, unresolved facts, and semantic review findings or explicit user overrides. Refer to the existing manifest/crop/review files for machine facts. Keep PID checks, database/history coverage, file paths, retries, billing, submission status and measured QC limitations out of `--prompt-text`. Preserve visible garment facts and concrete reference/photography constraints in the script. Report operational outcomes in the final task summary and existing status/QC artifacts. When revising prepare, update notes if their facts or review findings changed; omission preserves previous notes.

Use this sequence, keeping RUN inside the task's local output directory:

0. `catalog.py --pid EXACT_PID` returns the indexed product record and previous channel videos from the configured database. Treat imported price/stock as historical, and still verify the current shop product. If the catalog is not enabled or has no matching product, continue browser lookup; do not ask for either original Excel file.
1. `collect_product.py --pid EXACT_PID --run-dir RUN --output RUN/product-contact-sheet.jpg` reads the authenticated shop's exact PID detail page, verifies its URL/title, downloads original photos, and returns paths plus `product/manifest.json`. Inspect the registered contact sheet with `inspect_generated_image` to identify garment structure and the lowest-index complete frontal photo. Product records and previously written prompts are not required from the user.
2. Use `crop_garment.py` on that original, with visually chosen bounds and `--output RUN/garment-crop.jpg --metadata RUN/crop.json`. Inspect the crop, including neckline/shoulders/hem. Both images are reference artifacts, not generated clothing or final deliverables.
3. Use the complete script specification injected into your instructions (standalone use: read the canonical document linked in `references/script-rules.md`), then write the full prompt in that document's language and format from verified garment facts and the supplied identity. Agent Node supplies the selected rules file to prepare/submit automatically; omit --rules-file in Agent tool arguments. Compare available catalog speech and previous prompts for repeated Hook, pain point, dialogue, detail order and CTA; report incomplete history. Choose DURATION_SECONDS from the current user request, otherwise from the selected Markdown duration requirement (a range allows a choice within that range, honoring any preferred value). Keep the prompt timeline and speech within that duration; do not copy 15 seconds into every video type. Save it with `run.py prepare --run-dir RUN --pid EXACT_PID --prompt-text FULL_PROMPT --duration DURATION_SECONDS`. This creates `prompt.txt`, `workflow.json`, `analysis.json`, `status.json` and `prompt-review.json` using the node's bundled API template. Review returned structure warnings, correct accidental omissions with prepare, and assess semantic compliance before submitting. Current explicit format overrides may explain warnings; a clean structure report alone is not creative approval. Never retain the template's example clothing or dialogue.
4. `run.py submit --run-dir RUN --pid EXACT_PID --face INPUT_FACE --garment RUN/garment-crop.jpg` automatically uses the prepared workflow, prompt and duration. Omit --duration here to preserve the prepared value; if timing changes, revise the prompt and prepare again. The node injects the actual invoking account's temporary session and current instance URL; omit `--base-url`. Never choose an account from prompt text or print credentials. Submission errors must be reported, not automatically retried.
5. `run.py poll --run-dir RUN --wait-seconds 120` waits for the existing job; repeat polling only while pending. On completion, `download_video.py --run-dir RUN` registers the actual MP4. If generation failed, report it without resubmission.
6. Return the downloaded video for human confirmation. Do not call Gemini, `gemini_qc.py`, or another model for video/audio quality review or transcription. Publication and database delivery happen after the skill returns; do not claim human approval or automatically regenerate a video.

Agent Node persists its state/artifacts and returns the final summary as text. After the skill returns, the node handles OSS publication and, when `tiktok_database.enabled` is configured, records the video in the configured channel database automatically. Do not modify Excel or write the database from the Agent; do not also call `publish_oss.py`. The node deduplicates by generation task ID and reports the assigned channel sequence. Excel is an on-demand export, not the live record store. Database/publication failures must not erase a generated video or trigger regeneration.

A browser login challenge requires the shop account owner to authenticate the configured profile. Do not run interactive `--login` inside the Agent tool. If lookup fails, report the actual collector error and keep the run directory. Do not infer missing garment facts from the identity photo. A video child task requires a free scheduler worker and available account concurrency.

## Execution

1. Create an isolated run directory and `status.json` immediately. Record stage, prompt ID, artifact paths, errors and timestamps incrementally. Keep credentials in environment/config, out of stdout and artifacts.
2. Treat PID as a string throughout. For a directly supplied PID, require the collector to match the exact detail-page PID and title. When resolving a PID from source records, require an exact unique record match as well. Do not round, infer missing digits, or use JavaScript numbers for a 19-digit PID. Reuse verified original photos and their manifest.
3. Choose the lowest-index valid frontal image with the complete garment. Use Pillow cropping only, retaining shoulders, neckline and hem while removing eyes/nose/mouth. Save normalized and pixel bounds, preserve the original, and visually inspect the result. A detail shot is not a complete garment reference.
4. Keep identity and clothing images separate. Identity comes from the supplied face and visible proportions; clothing comes from the cropped product image. Do not substitute a generic Western model or invent unseen body proportions. Follow the selected document's output structure and language, and synchronize prompt timing with node duration. The default fashion document uses a full Chinese prompt, translations only in section 8, and a speech budget matched to the selected duration (roughly 30–36 natural English words at 15 seconds, allowing pauses). Other documents may use different sections and languages. Claims require visible structure or verified facts.
5. Authenticate ComfyUI using the injected task session in Agent Node; standalone CLI uses form-encoded `/login` and `jwt_token`. Upload inputs and validate against authenticated `/object_info`. Preserve the original workflow. Tested bindings: face 79, garment 78, generation 61, preview 77. Output duration supports integer seconds from 2 to 30, or -1 for smart duration when requested. The selected Markdown supplies the preferred duration for its video type; the standalone prepare fallback is 15 seconds. Tested settings: `3.0-prime`, 720P, 9:16, audio enabled, prompt enhancement disabled. Current user choices override defaults and the reference document's 60 fps preference; report measured frame rate only.
6. Submit within existing user authorization. Before `/prompt`, persist the rendered workflow, SHA-256 intent and client ID. Write returned prompt ID immediately. Never automatically retry an unknown POST, a failed paid job, or a disappointing result. Resume existing history/task. Do not delete the intent guard to make a retry work.
7. Download actual output with `download_video.py`; it registers `final.mp4` and reads basic local media metadata into `ffprobe.json` without an AI call. It can resume an existing MP4 without another generation or download. Preserve the video if duration/audio metadata has warnings.
8. Human reviewers confirm garment, identity, shot count, mouth synchronization and prohibited text/music. Report the video as awaiting human confirmation; never infer approval from generation success.
9. Prefer a verified existing public Comfy output. Otherwise publish the final asset to configured OSS public storage and verify unauthenticated GET, MIME type and exact bytes/hash. An expiring signed URL is not a permanent publication URL.
10. Preserve the product manifest, original first product photo, `analysis.json`, `job.json`, `prompt.txt`, `post-copy.json` and `final.mp4` for the node's database writer. Chinese body copy comes directly from section 8 and English body copy from section 7 of `prompt.txt`, retaining speaker labels and line breaks but excluding chapter headings. Posting caption and hashtags come from `post-copy.json`. Do not generate these fields from the video or QC. Use `export_excel.py` outside the Agent when export is requested.

## Human-dependent boundaries

Persisted TikTok login can expire and OTP may require the account owner. Do independent cached-input work while blocked. Use existing authorization without an extra approval ceremony; seek new authorization only outside that scope. Quality defects may need human acceptance, especially unclear speech or identity mismatch. One completed run does not establish general unattended reliability.

Media helpers use requests, Pillow and PyAV. Catalog queries and Excel export use the tiktok-ops API; the local SQLite outbox stores only delivery events.
