# 视频规则文件的维护与检查

每份视频规则独立保存为节点 `workflow/` 目录内的一份 Markdown 文件。新增规则只需新增 `.md`，无需注册表、JSON 配置或新的 Python 分支。默认使用 [美国 TikTok Plus Size UGC 视频脚本规范](../../../workflow/美国TikTok_PlusSize_UGC视频脚本规范.md)，不复制正文。

在用户请求中单独写一行选择文件（相对于 `workflow/`，支持子目录）：

```text
规则文件：开箱视频规则.md
按照这份规则生成视频。
```

上面的开箱文件名仅为示例，需要先创建对应文件。也可指定 `workflow/` 内文件的绝对路径。没有指定文件时使用默认的 Plus Size UGC 规范；指定文件不存在则报错，不回退到其他规则。一次任务选择一份规则。

Agent Node 每次执行都通过 `fashion_prompt.py` 读取所选文件全文并注入模型指令，自动将同一文件传给 prepare/submit。不要在 Agent 的脚本参数中重复添加 `--rules-file`。本次用户明确要求只覆盖对应部分。规则文件可使用各自的章节、语言和拍摄要求，不必统一为默认规范的十三部分。

独立命令在节点根目录运行：

```text
python fashion_prompt.py list
python fashion_prompt.py show --rules-file "开箱视频规则.md"
python fashion_prompt.py check --rules-file "开箱视频规则.md" --prompt RUN/prompt.txt --duration DURATION_SECONDS
```

独立 CLI 的 `run.py prepare` 同样支持 `--rules-file`；`run.py submit` 未传此参数时继承准备阶段的文件，显式换文件需重新 prepare。Agent 外部使用本技能时，也须先读取所选规范全文。

`DURATION_SECONDS` 应替换为本次选定的秒数：先遵循用户明确要求，否则遵循当前 Markdown 的时长要求。范围允许在范围内选择，有优先值时优先采用；其他规则文件不继承默认规范的15秒偏好。Agent 在 prepare 时显式传入选定时长，submit 省略 `--duration` 即继承工作流中的时长。独立 CLI 的 prepare 未传时长时才使用15秒兜底，不会自行从 Markdown 解析时长。当前生成节点支持2–30整数秒，也支持 `-1` 智能时长；智能时长不按固定秒数检查口播预算或成片时长偏差。提示词的基础设定、分镜时间轴及口播应与实际生成时长一致。

`prompt-review.json` 与 `prompt-submit-review.json` 保存所选文件名、规范全文及 SHA-256、提示词 SHA-256 和辅助检查结果。新增或修改 Markdown 无需重启，下一次执行读取最新内容。

`run.py prepare --prompt-text FULL_SCRIPT --wan-prompt-text ENGLISH_SHOOTING_PROMPT --execution-notes NOTES` 同时保存完整创作脚本 `prompt.txt` 和实际提交给 Wan 的纯英文拍摄指令 `wan-prompt.txt`。英文版是完整翻译，不是精简或重组：仅删除默认规范第7部分重复口播汇总和第8部分中文翻译，其余标题、章节、子章节、字段、列表、分镜细节和限制全部按原顺序与层级保留并翻译成英文。大章节使用阿拉伯数字1–6、9–13，保留编号空缺，不重新编号。服装判断、基础设定、人物穿搭、场景剧情、拍摄表演、完整分镜、整体表演、声音、一致性、负面提示词和最终执行要求均完整保留；第13部分逐镜执行汇总即使与第6部分重复也不得删减、合并或压缩。已有英文对白和英文负面提示词逐字保留，不从中文参考重新生成台词。其他规范仅按用途排除对应的口播汇总及翻译章节，其余结构和内容完整保留。在声音或最终执行要求中明确：只有标明的逐镜对白可以被说出，其余内容均为拍摄指令。prepare 和 submit 将这份完整英文文本直接传给 Wan，不再提取、删节或截断。

prepare 和 submit 都检查英文版非空且无中文/CJK字符，并记录两份文本的 SHA-256；任一文本修改后必须一起重新 prepare，旧的未提交任务缺少英文版也需要重新 prepare。已提交任务继续 poll/download，不重新生成。Agent 须逐章逐字段核对剩余内容是否全部翻译、语义是否一致、英文台词是否原样保留；字符检查不能证明翻译正确或完整。数据库仍从 `prompt.txt` 提取中英文文案，不读取 `wan-prompt.txt`，无需修改数据库。

核验依据、裁剪选择理由、去重范围、未确认事项和复核说明仍保存到 `execution-notes.md`。修改脚本时省略 notes 参数会保留已有说明。商品原始信息、裁剪坐标、提交结果和质检结果仍使用各自的记录文件。创作脚本中保留可见商品事实和具体拍摄限制，不混入程序执行汇报。

发布文案与标签使用独立的 [TikTok发布规则](../../../workflow/TikTok发布文案与标签规则.md)，由 runtime 另行读取并注入，每次任务读取最新内容。prepare 同时传入 `--caption-text` 和 `--hashtags`，保存到 `post-copy.json`，不进入视频提示词。数据库主体英文/中文分别直接读取 `prompt.txt` 第7/8部分，不调用 Gemini 反推；成片由人工确认，自动流程不调用音画质检模型。

辅助检查会识别 Markdown 中以“输出结构”结尾的二级标题，以及其中的 `1. 标题：说明` 或 `1. 标题` 列表；这只是可选的机器检查格式，不是所有规则必须采用的模板。只有文档列出的章节才参与检查；英文口播预算只检查文档定义的“英文口播”部分。未识别结构时会说明跳过检查，模型仍须审核全文。默认规范中的集中翻译要求按其中明确写出的句子检查，其他文档不自动继承。

输出结构内可用 `| 章节编号 | 字段一；字段二 |` 表格声明独立成行的章内字段，未声明则不检查。分镜章节按 `【分镜…】` 标题逐镜检查这些字段。脚本大章节统一使用二级标题，人物和分镜用三级标题，以免人物编号被当作大章节。声明“执行记录单独保存”的规范还检查常见操作说明混入问题；这不是完整语义检测。口播字数不计行首说话者标签。

结构检查是提示，不能证明 Hook、商品事实、去重或成片合规。历史去重使用可用 catalog 口播及历史脚本；无历史或记录不全须说明范围。实际时长、帧率、音频和视觉表现以成片检测为准。
