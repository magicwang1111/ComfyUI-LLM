# 视频脚本参考库

把优秀视频脚本直接放进本目录，一篇一个 `.md` 或 `.txt` 文件，保存为 UTF-8（允许 BOM）。可用中文文件名和分类子目录，不需要填写 JSON、注册表或修改代码。

例如：`001_门口偶遇.md`、`002_朋友试穿.txt`、`连衣裙/003_约会出门.md`。文件正文直接放完整脚本；可自行在开头补充适用品类、场景、Hook 或优秀之处，非必填。

- 每次执行 `tiktok-fashion-video` 时，按相对文件名排序、全文加载全部脚本，不随机抽取、不截断。新增、修改或移除文件后，下次任务自动生效；运行中的任务保留已加载内容。
- 空目录、空文件不影响生成。以 `_` 或 `.` 开头的文件或目录不加载，因此本说明不会进入参考内容。暂不使用的脚本可改名为 `_文件名.md`。
- 仅读取 `.md`、`.txt`，不读取 Word、PDF 或视频文件；其他格式先导出为 UTF-8 文本。最终生成结果放任务输出目录，不要自动回填本库。
- 脚本存放在实际运行 Agent 的机器上。若 Agent 在 Linux 服务器执行，需要把本目录同步到服务器对应的技能目录；只改 Windows 本地目录不会改变远程实例。

## 缓存与检查

有参考脚本时，节点将其放在固定指令中，商品 PID、任务要求、图片和输出路径放在后面的用户消息中。相同固定指令使用稳定的 `prompt_cache_key`，并发送 `prompt_cache_retention: "24h"`。这只是向 Vapeur 请求保留策略，不保证实际命中 24 小时；没有定时续费、保活或缓存重建任务，缓存由 API 在实际调用时处理。

每个请求仍发送参考全文。新增、修改、删除、重命名脚本或更换规则会改变固定指令，可能需要重新创建缓存。模型设置、工具变化和服务端路由也会影响命中。全部上下文超过 272k 时，6-astra 可能进入更高价格档位，应以平台用量与账单为准。

任务日志显示已加载篇数，任务目录的 `script-references.json` 保存文件名、内容 SHA-256、字符数和缓存参数。字符数不是 Token 数；缓存是否命中应查看 API usage 或 Vapeur 用量明细，不能仅凭返回 `24h` 判断。

参考只用于借鉴故事、Hook、展示方法和镜头节奏，不作为当前商品事实，也不替代历史去重。当前用户要求、选定视频规范和已核验商品信息优先。Agent 在 `execution-notes.md` 记录实际借鉴的参考与历史对比，最终视频提示词只保留新创作的脚本。
