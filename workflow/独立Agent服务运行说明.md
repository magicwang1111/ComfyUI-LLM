# 独立 Agent 服务

实现入口：`agent_service.py`。代码在 LLM 插件目录内独立运行，不启动另一个 ComfyUI，不在插件导入时自动启动。

## 启动

同时更新 ComfyUI-LLM 和 ComfyUI-Account-Manager，重启使用这些插件的 ComfyUI 实例，然后单独启动服务。Account Manager 必须已启用分布式队列；首版要求编排服务与这些实例在同一台机器，共享输入、输出和插件路径。

Windows，在插件目录执行：

```powershell
.\start_agent_service.ps1 -Port 8195 -BaseUrl http://127.0.0.1:8180
```

需要指定 Python 时追加 `-Python D:\miniconda3\envs\comfyui\python.exe`。默认优先使用插件的 `.agent_env`，依赖沿用 `requirements-agent.txt`。

Linux：

```bash
bash start_agent_service.sh --port 8195 --base-url http://127.0.0.1:8180
```

`--port` 是新增服务的本地健康检查端口，默认 **8195**，程序拒绝使用 **8180–8190**。`--base-url` 是已有 Account Manager 的访问地址，不是新增监听端口；按实际入口修改。访问 `http://127.0.0.1:8195` 可以查看连接状态及本进程正在处理的任务数。先绑定端口再领取任务，端口占用会直接报错退出。

服务读取 Account Manager 的 `scheduler_secret_file` 配置，使用现有内部签名与任务接口通信；不需要填写用户密码。非默认密钥位置也可使用 `agent_service.py --secret-file PATH`。仅支持回环地址。不要公开密钥文件和任务数据库。

启动脚本持续运行，关闭它会停止本地 Agent 执行。生产环境应由已有的进程管理器守护此命令，并将输出写入服务日志。只需启动一份；意外启动多份时数据库仍统一执行并发限制。

## 前端使用

新增节点类型 **`ComfyUI-LLM Agent Task`（独立 Agent 任务）**。参数与原 Agent 节点相同，可以连接上游图片。执行时将输入落盘并提交独立任务，立即输出 `task_id`，释放当前 ComfyUI 执行位置。

节点内每 3 秒查询一次任务状态和增量日志，展示视频子任务的排队/执行状态。完成后显示文本、费用、图片和视频预览；支持取消、任务历史，以及恢复已有视频/交付。页面关闭不取消任务。工作流保存的节点属性包含任务 ID；若刷新前尚未保存，可通过“任务历史”重新选择任务。

新节点输出的是任务 ID，不能连接到要求最终 `IMAGE` 或 `VIDEO` 的旧下游节点。首版通过节点面板交付结果，TikTok 视频归档和数据库回填由后台完成。其他后处理应使用已完成文件另起工作流。

旧 `ComfyUI-LLM Agent SDK` 节点保持同步输出，仍会占实例。迁移视频生产流程时应换成新节点；旧同步视频 Agent 不受本方案的独立队列保护，不应与新模式混跑到占满全部实例。

## 容量与数据

Account Manager `config.json` 可选设置（不填写则使用这些默认值）：

```json
{
  "agent_tasks_db": "agent_tasks.sqlite3",
  "agent_concurrency": 4,
  "agent_concurrency_per_user": 2,
  "agent_pending_per_user": 20
}
```

Agent 等待视频期间占一个独立 Agent 并发额度，不占 ComfyUI 实例。视频执行继续遵守现有调度器的实例、资源类型和账户限制。4 个视频实例全忙时，新视频正常入队。

任务、租约、日志、子任务关联和结果保存在 Account Manager 的 SQLite 数据库中。服务每 5 秒续约，租约 90 秒；联系后台超过 60 秒失败时停止 Agent，避免失联后继续操作。任务凭据只传入子进程环境，绑定 owner、任务和租约；任务结束后失效。

## 中断与恢复

- 正常取消会停止 Agent 及其本地子进程，移除尚未执行的视频，并向已运行视频发送定向中断请求。供应商已接受的视频可能继续运行和计费，面板继续展示其实际状态。
- Agent 已完成、交付前中断：保存的结果检查点可恢复交付，不再运行模型或生成视频。后台确认进入交付阶段后，服务重启会自动接管交付。
- 视频已经提交、Agent 中断：任务标记“待恢复”；点击“恢复已有视频／交付”，仅恢复已绑定 TikTok 视频的查询、下载和回填。使用原脚本、文案和视频任务 ID，不提交新视频。
- 模型或工具在其他步骤中断：保留事件和产物，标记待恢复。首版不恢复任意 Agent 对话中间状态，也不会自动重新执行可能付费的操作。
- 服务器已入队但提交响应丢失：服务端预先记录的子任务 UUID 可关联已有任务。相同 `client_id` 的重复提交不会生成第二条任务；无法确认入队结果时返回冲突，要求核对。
- 数据库回填使用现有持久投递机制；面板会提示待投递和交付警告。生成完成不代表人工审核或发布完成。

更新或回退前先停止新提交，等待在途任务结束，或明确取消并核对仍在运行的视频。不要删除任务数据库或在途产物目录。
